AI Design Language Overview

Principles, maturity model, and decision framework for integrating AI features into the Rosewood product suite.

Why an AI Design Language?

A unified AI design language ensures that every AI-powered feature across the Rosewood product suite delivers a coherent, trustworthy, and predictable experience. Without shared principles and patterns, AI capabilities risk feeling fragmented, inconsistent, or opaque to the users who depend on them daily.

Core Design Principles

These principles guide every decision when designing and building AI-powered features within Rosewood. They establish the foundation for user trust and product quality.

Principle Description
Transparency AI actions and reasoning should always be visible to users
User Control Users must be able to override, undo, or dismiss AI suggestions
Graceful Degradation Features must remain functional when AI is unavailable
Progressive Trust Build user confidence through incremental AI exposure
Consistency AI interactions should follow predictable patterns across surfaces
Accessibility AI features must meet WCAG 2.1 AA standards

AI Maturity Model

[Insert maturity model diagram: Level 1 Assistive → Level 2 Augmentative → Level 3 Autonomous]
Level Name Description Example
1 Assistive AI provides suggestions that require explicit user action to accept. The user remains fully in control of every decision. Autocomplete suggestions for client search fields
2 Augmentative AI takes proactive actions on behalf of the user but always allows review, modification, or reversal before committing. Smart scheduling that proposes an optimized staff roster for review
3 Autonomous AI executes decisions independently within well-defined guardrails, notifying the user of actions taken. Automated no-show follow-up messages sent after configurable rules are met

When to Use AI

[Insert decision tree diagram]

Use the following checklist to determine whether AI is the right solution for a given feature:

  • The task involves pattern recognition, prediction, or large-scale data processing that would be impractical manually.
  • There is sufficient historical data available to train or inform the AI model.
  • The cost of an incorrect AI suggestion is low, or safeguards can adequately mitigate risk.
  • Users have expressed pain around the manual version of this workflow.
  • The feature can degrade gracefully if AI is unavailable or produces low-confidence results.
  • The AI output can be clearly explained and attributed so users understand why a suggestion was made.

Quick Start

  1. Review the Core Design Principles above to align on shared values.
  2. Identify the AI maturity level appropriate for your feature.
  3. Consult the decision framework to confirm AI is the right approach.
  4. Check the Usage by Surface page to see existing patterns for your product area.
  5. Reference the Visual Specs for component-level guidance on AI indicators, loading states, and feedback patterns.
  6. Prototype and test with real users, paying close attention to trust and transparency.
